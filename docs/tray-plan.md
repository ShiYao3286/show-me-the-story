# 开发计划：Windows 系统托盘

> 状态：**核心功能已实现**（步骤 1–5 完成；开机自启 6、CI 矩阵 7 待做）
> 记录时间：2026-10-18
> 目标版本：未定（建议 `v4.1.x`，属功能级改动）

## 1. 为什么做

当前启动方式是「运行 exe → 自动打开浏览器」。这有两个体验缺口：

1. **关掉浏览器窗口后，服务仍在后台跑**，但用户看不到它——没有可见的入口可以再次打开界面，也没有办法确认它在运行。只能去任务管理器杀掉进程。
2. **没有「退出」入口**。用户不知道该怎么正确停止程序，容易直接杀进程，而杀进程可能打断正在进行的保存或 AI 任务。

系统托盘解决的正是这两点：常驻图标 + 右键菜单（打开界面 / 打开数据目录 / 退出）。

## 2. 现状与约束

先明确本项目与常见 Electron 应用的区别，这决定了实现方式：

| 项 | 现状 |
|---|---|
| 程序形态 | **Go 单二进制**（`-H windowsgui`，无控制台），不是 Electron |
| 界面 | 外部浏览器（`rundll32 url.dll,FileProtocolHandler http://localhost:48090`） |
| 端口 | 默认 `:48090`，`PORT` 环境变量可覆盖 |
| 退出方式 | 目前只能结束进程；没有信号处理 |
| 已有依赖 | Go **标准库 only**，无第三方模块 |

**关键约束**：项目坚持「零第三方依赖 + 标准库」。托盘必须用 Win32 API（`Shell_NotifyIcon`），不能引入 `systray` 之类的库，否则会破坏这一约定，也可能影响交叉编译（当前 5 个目标平台都能一条命令构建）。

**Windows 托盘 API 可行性**：用 `syscall`/`golang.org/x/sys/windows`… 但后者是外部模块。**纯 `syscall` 可以做到**：`RegisterClassEx` → `CreateWindowEx` → `Shell_NotifyIcon` → `GetMessage` 循环。需要在主 goroutine 上跑消息循环（Win32 要求），HTTP 服务继续在另一个 goroutine。

## 3. 设计方案

### 3.1 总体结构

```
main.go
├── 平台判断：windows 且非 -no-tray 时启用
├── goroutine A: httpapi.StartWebServer(...)   ← 现有逻辑不动
└── goroutine B (主线程): tray.Run(...)         ← 新增，Windows 消息循环
        ├── 托盘图标（复用已嵌入的 icon.ico / icon_16.png）
        ├── 左键单击 / 双击 → 打开浏览器
        └── 右键菜单
             ├── 打开写作界面
             ├── 打开数据目录
             ├── 打开日志（若 devlog 启用）
             ├── ────────────
             ├── 关于（版本 / 端口）
             └── 退出
```

### 3.2 退出流程（这块最需要设计）

托盘「退出」必须**优雅关闭**，不能直接 `os.Exit`：

```
点击「退出」
  → 检查是否有 AI 任务在跑（复用 httpapi 的 isTaskRunning）
      ├── 有 → 弹确认「有任务正在运行，退出可能中断保存。仍要退出？」
      │        ├── 取消 → 什么都不做
      │        └── 确认 → 继续
      └── 无 → 继续
  → 通知 HTTP 服务优雅关闭（srv.Shutdown(ctx)，给 5–10s 让正在写的请求完成）
  → 移除托盘图标（Shell_NotifyIcon NIM_DELETE）
  → 退出进程
```

**为什么重要**：存储层有 `progress.json.rollback` 事务保护（未提交的保存会在下次加载时回滚），但**正在写入的那一刻被杀**仍可能留下需要恢复的状态。优雅关闭能让用户少一次「打开时提示恢复」的惊吓。

当前 `StartWebServer` 是阻塞调用且不返回 `*http.Server`，需要**改造成可关闭**：

```go
// 现在
func StartWebServer(...) { ...; srv.ListenAndServe() }

// 改成
func StartWebServer(...) *http.Server   // 或返回一个 shutdown 函数
```

这是本功能**唯一需要改动的现有代码**，约 10–20 行，风险低。

### 3.3 「关窗口 = 隐藏到托盘」？

本项目没有自己的窗口（界面在浏览器里），所以**传统意义的「关闭窗口时隐藏」不适用**。

可选增强（低优先）：检测浏览器标签页是否还开着——这做不到可靠检测。所以**不做**，改为在托盘菜单里明确提供「打开写作界面」，用户关掉浏览器后点托盘图标即可重新打开。

### 3.4 开机自启（可选，默认关闭）

托盘常驻后，用户很可能想「开机自动启动」。两种做法：

| 方式 | 实现 | 取舍 |
|---|---|---|
| 注册表 Run 键 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 简单，但卸载时要清理；安全软件可能提示 |
| 启动文件夹快捷方式 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` | 更透明，用户能自己删 |

**建议用启动文件夹**，且**默认不开启**，由托盘菜单的勾选项控制。理由：这是写作工具，不是常驻后台服务，强行自启会惹人烦。

### 3.5 非 Windows 平台

- Linux / macOS：**保持现状**（无托盘）。这两个平台当前就是「终端里跑，Ctrl+C 退出」，已够用。
- 用 `//go:build windows` 把托盘代码隔离在单独文件，避免影响其他平台的构建。

## 5.1 实现过程中发现的环境陷阱

**在受限目录下启动的进程会被降权到 Low 完整性级别，`Shell_NotifyIcon` 一律返回 `ERROR_ACCESS_DENIED`。**

实测对照：

| 可执行文件位置 | 进程完整性 | Shell_NotifyIcon |
|---|---|---|
| `E:\ai处理文件\...`（受限路径） | Low | 失败（Access denied） |
| `%TEMP%` / `C:\Windows\Temp` | Medium | 成功 |
| `C:\Windows\System32\notepad.exe` | Medium | — |

诊断技巧：故意传非法参数（`cbSize=0`、`hWnd=0`）。若仍返回 `ERROR_ACCESS_DENIED` 而非 `ERROR_INVALID_PARAMETER`，说明调用在参数校验之前就被拒绝，是进程权限问题而非代码 bug。

**部署影响**：正常安装到 `C:\Users\...\AppData\Local\` 或 `E:\小说\...`（用户目录）不受影响；只有沙箱/受限工作目录才会触发。

## 6. 需要提前确认的技术点

开发前应先验证这几件事，避免方向错误：

1. **纯 `syscall` 实现托盘是否可行** —— 需要 `RegisterClassExW`、`CreateWindowExW`、`Shell_NotifyIconW`、`TrackPopupMenu`、`GetMessageW`。这些在 `syscall` 包里都有对应，但结构体定义要自己写。**建议先写一个最小 demo（显示图标 + 退出）验证**，再进入正式实现。
2. **无控制台进程里弹出 MessageBox 是否正常** —— `-H windowsgui` 下用 `MessageBoxW` 应该没问题，但要测。
3. **图标来源** —— 现在已有 `build/windows/icon.ico` 与 `icon_16.png`（CI 生成）。托盘需要运行时能拿到图标资源。两个方案：
   - 把 16px PNG 用 `//go:embed` 嵌进二进制（推荐，简单）
   - 从 exe 自身资源里 LoadIcon（省体积，但代码复杂）
4. **消息循环与 HTTP 服务的线程关系** —— Win32 消息循环必须在创建窗口的同一线程。Go 的 goroutine 可能被调度到不同 OS 线程，需要 `runtime.LockOSThread()`。

## 7. 不做的事

明确排除，避免范围蔓延：

- **不做「关闭浏览器自动退出」** —— 无法可靠检测，且用户可能同时开多个标签页。
- **不做托盘气泡通知** —— 现有 SSE + 页面内 Toast 已覆盖，托盘通知是重复渠道。
- **不做 Linux/macOS 托盘** —— 当前平台用法是终端运行，无痛点。
- **不引入 `getlantern/systray` 等第三方库** —— 会打破零依赖约定，也影响交叉编译。
- **不改成原生窗口应用（WebView2）** —— 那是独立的一步（见下方「相关但独立」）。

## 8. 相关但独立的议题

以下与托盘相关但**应分开决策**，不要混在同一个改动里：

| 议题 | 说明 |
|---|---|
| **WebView2 原生窗口** | 把浏览器界面包进程序自己的窗口，体积 +2–4 MiB、需引入 Go 依赖。若做了这个，「关窗口隐藏到托盘」才成立 |
| **默认监听 127.0.0.1** | 当前绑 `0.0.0.0`。托盘常驻会让人以为「这是本地应用」，安全默认值更该修 |
| **单实例锁** | 现在重复双击会启动第二个进程抢端口（第二个会失败但收不到提示）。托盘化后更需要单实例：再次启动应唤起已有实例而非报错 |
